## 增强模式的实现细节

1. **中英文分词。** 对连续汉字同时按单字和相邻两字建索引。例如，查询“香港”可以匹配没有空格的“介紹香港”。拉丁字母单词、数字和 `GPT_4` 这类标识符保留原有词边界。两种模式分别从已存储的片段构建内存中的 BM25 索引。替换文档后，该资料库的索引会在下次检索时重建。切换模式可以复用已存储的向量。
2. **候选片段重排。** 两路检索完成倒数排名融合（RRF）后，增强模式最多取 `RETRIEVAL_CANDIDATES` 个候选，默认 24，可设为 6–100。评分器在 CPU 上运行，读取查询的前 512 个字符、正文的前 1,000 个字符和标题的前 150 个字符。词法得分由三部分组成：正文对查询词的加权覆盖率占 65%，相邻查询词对按原顺序出现的比例占 25%，标题对查询词的加权覆盖率占 10%。词权重取自逆文档频率（IDF），并设有正数下限。查询只有一个词时，词对部分采用正文覆盖率。最终重排分数中，词法得分占 70%，其余 30% 来自融合排名，候选越靠前，这项分数越高。评分器使用项目现有依赖，同步处理候选片段。评分出错时，运行轨迹会记录该次工具调用失败。
3. **证据去重与来源选择。** 当片段 ID 相同，或原文在统一空白字符后相同时，保留排名最高的一条。大小写、标点和数字差异均会保留。如果下一条片段来自已经选过的来源，只有当另一来源的候选词法得分大于零，且两者的重排分差在 `RETRIEVAL_DIVERSITY_MARGIN` 以内时，才优先选取新来源。该参数默认为 0.04，范围为 0–0.1，设为 0 即关闭来源优先规则。同一来源中内容互补的片段仍可入选。每条证据保留原片段 ID、来源 ID、原文和引用位置。去重后允许返回少于六条结果。

通过 `/api/status` 可以查看当前生效的配置，每份研究结果也会记录检索设置。文件检索的调用轨迹中，`candidate_count` 是送入重排的候选数（基线模式记录返回条数），`rerank_ms` 是重排和证据选择的合计耗时，`elapsed_ms` 是整次工具调用耗时。证据中的 `score` 为原始融合分数，`semantic_score` 为向量相似度。增强模式另有 `lexical_score`（词法得分）和 `rerank_score`（调整来源顺序前的综合重排分数）。

## 在服务器上复现

在目标服务器的项目根目录下执行以下命令，使用已安装项目依赖和 pytest 的 Python 环境。记录实验结果时，一并保留提交号或工作区补丁、CPU、内存和嵌入模型名称。

```sh
python -m pytest -q tests/test_retrieval.py tests/test_agent.py tests/test_evaluation.py
python -m eval.compare_retrieval --output outputs/retrieval-dev-01
```

第二条命令需要能访问配置的嵌入模型。它只对固定开发语料计算一次向量，预热两种模式的索引，再逐题交替两种模式的测量顺序。两边使用相同的向量、证据标注和返回条数上限。请使用新的输出目录，其中会保存 SQLite 语料库和 `comparison.json`。后者包含评测数据的哈希、检索配置、按排名排列的片段 ID 及逐题指标。

| 指标 | 如何解读 |
| --- | --- |
| Recall@6 | 前六条结果找回的标注证据占全部标注证据的比例。每条标注由来源 ID 和句子 ID 共同确定。 |
| MRR@6 | 对每道题取前六条中第一条标注证据的排名倒数，再对各题取平均。首条即命中记为 1，前六条均未命中记为 0。 |
| 相关来源覆盖率 | 有标注证据被找回的来源数，占全部标注来源数的比例。 |
| 重复片段占比 | 按上述空白字符规则比较正文，计算重复片段占返回条数的比例。 |
| 预热后检索耗时 | 两种索引预热后，测量单次检索耗时。 |

`eval/retrieval-dev.json` 含六道由开发者标注的题目，覆盖中文、英文、中英混合输入和双文档比较。独立验收时，先固定检索参数，再通过 `--fixture` 传入相同格式、独立标注的题目，并指定新的输出目录。分别检查各语言组、多文档题及表现退步的个例。默认向量模型面向英语，中文关键词命中提供的证据只覆盖中文语义检索能力的一部分。

端到端比较需要在服务器配置生成模型 API。先以 `baseline` 启动应用并执行第一条命令，再切换到 `enhanced`，重启应用并执行第二条。两次使用相同的生成配置和资料库。逐题核对实际引用的原文片段、回答及 token 用量。后续实验请使用新的输出目录。

```sh
python -m eval.run --api http://127.0.0.1:3000 --dataset hotpotqa --split dev --limit 4 --modes single_rag --output outputs/e2e-baseline-01
python -m eval.run --api http://127.0.0.1:3000 --dataset hotpotqa --split dev --limit 4 --modes single_rag --output outputs/e2e-enhanced-01
```

示例中的 3000 是本次 InstaBox 部署使用的端口。其他部署请将 `--api` 替换为实际服务地址。
