# 2026-11-17：联网研究与无答案反馈修复

用户反馈 `RSI-index有哪些现存的work` 没有生成答案。原始记录
`45f1e7137bf340be9c3b3dc6642f369c` 保留不变：模型请求成功，但三次
`search_web` 均返回 `No results found.`，本地 Demo 资料也不覆盖该问题，
因此答案为空。用户随后明确其含义为 RSIGym / Recursive Self-Improvement。

## 原因和修复

- 免费网页搜索受到反爬和限流影响，旧工具未提供足够的供应商诊断信息。
  现在保留 DDGS 通用搜索，并在没有可用结果时尝试 arXiv 论文搜索；后备来源
  只覆盖 arXiv，不等于完整互联网。两者共享最多 15 秒的时限，不新增 API 密钥。
  行动轨迹记录供应商、范围和逐次结果；搜索摘要仍不作可引用证据。
- 检索到的无关 Demo 内容影响了规划主题。联网规划现在明确以用户问题为准，
  不用课程背景或无关片段解释缩写，并将具体工具错误与结果数量传给规划器。
- 搜索结果不是可引用证据，但新发现的网页仍代表检索进展。现在允许后续决策
  读取这些网页；重复 URL 不延长流程，原有轮次和工具预算保持不变。
- 网页工具兼容模型返回的 `url` 单数键或 `urls` 字符串，统一转换为单元素
  `urls` 数组后再检查重复和预算。多 URL 调用仍明确报错，不静默丢弃来源。
- 数字候选检查允许使用已引用来源的标题与 URL，并统一完整 ISO、英文和中文
  日期，避免把日期连字符识别为负号。真实负数、百分号和完整年月日关系仍保留；
  不推算作者数量，仍要求语义检查和精确引文。联网起草把证据缺口放在未解决问题中，
  避免把有依据的结论与未查到内容的断言混在一起。
- 多篇文献综述的总回答可能合并多个声明的引用。总回答引用上限从 8 调整为 30，
  与单次研究的证据上限一致；单条声明仍最多 8 条引用。未截断或伪造引用。
- 页面不再把“运行结束但没有答案”展示为成功回答。结果区明确说明证据不足，
  区分本地材料不足和联网工具失败，并保留原始信息缺口和日志。
- 静态资源带版本参数，避免刷新后继续使用缓存中的旧界面。

## 验证

- Python 自动化测试：137 项通过（2.13 秒），包括单 URL 参数兼容、重复调用检查和
  22 个新增数字/日期回归样例。这些是软件行为验证，不是人工引用正确率评估。
- 前端结果分类与诊断测试：8 项通过；JavaScript 语法检查通过。
- 真实 arXiv 后备搜索原样查询 `RSIGym recursive self improvement`，成功发现
  原论文；从实际返回链接读取到 5 个正文片段。
- 浏览器验证原无答案记录现显示“未找到足够证据”、三次搜索无结果及本地片段
  不足的诊断，原记录未被重写。
- 修复后真实任务 `85d8a66d37ee494ba415b06d20003943` 用时 79.938 秒，完成
  10 次工具调用及 10 次模型调用，生成非空回答和引用。浏览器确认回答、23 条
  证据片段及行动轨迹可见，无浏览器脚本错误。记录见
  `docs/validation/rsi-fix-20261117.json`，完整输出见 `rsi-live-run-20261117.json`。
  回答覆盖 RSIGym 与几篇 RSI 综述，未穷尽相关工作；检查器的支持判定不是人工真值。
